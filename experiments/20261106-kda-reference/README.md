# 2026-11-06 KDA の実装と 10M の比較

## 目的

本命の線形層である KDA（Kimi Delta Attention）を MLX で実装し、参照実装と一致するか確かめる。あわせて、[Transformer の実験](../20261106-mini-10m/README.md)と同じ手順で学習して比べる。

## 実装

- [train/kda.py](../../train/kda.py)。チャンク形式を MLX の演算だけで書き、逆伝播は自動微分に任せた。Metal カーネルは書いていない。
- `mx.fast.gated_delta_update` の減衰はヘッドごとのスカラーなので、チャネルごとの減衰を持つ KDA には使えない。
- チャンク内の逆行列は、冪零の性質から行列積の繰り返しで求める。チャンクの大きさは 32。

## 参照実装との照合

flash-linear-attention（MIT）の `naive_recurrent_kda` と、同じ入力で比べた。

| 比較 | 最大の相対誤差 |
|---|---|
| 出力と、q、k、v、g、beta の勾配（4条件、逐次形式とチャンク形式） | 1.6e-6 |

条件は、小さな形、学習と同じ形（2×512×4×64）、強い減衰、チャンクで割り切れない長さ（77）。

照合したのは再帰の核だけである。層全体（短畳み込み、ゲート、出力の正規化）は参照のコードを読んで合わせたが、数値では照合していない。参照の層は Triton が前提で、Mac では動かない。

再現：torch と einops の別環境で `make_reference.py <naive.py のパス> <出力.npz>` を動かし、`.venv/bin/python experiments/20261106-kda-reference/compare.py <出力.npz>` で比べる。

## 学習の比較

データ、語彙、バッチ（4×512）、5,000 ステップ（約1,024万トークン）、学習率、種はすべて同じ。マシンは M2 8GB。

| 項目 | Transformer | KDA ハイブリッド |
|---|---|---|
| 構成 | 全8層が全注意、RoPE | KDA 3：全注意 1、NoPE |
| パラメータ | 10,621,184 | 11,042,456（+4.0%） |
| 検証損失 | 6.009 | **5.884** |
| 検証 bits-per-byte | 1.716 | **1.680** |
| 速度（中央値） | **18,779 トークン/秒** | 5,017 トークン/秒 |
| 所要時間 | **9.2 分** | 38.5 分 |
| ピークメモリ | **1.69GB** | 3.36GB |

KDA は 1,500 ステップあたりで Transformer を逆転し、そのまま最後まで前にいた。

## 読み方の注意

- 種は1つで、1回だけの比較である。差が再現するかはわからない。
- 同じトークン数での比較である。同じ時間で比べると Transformer は約4倍のトークンを学習でき、順位は逆転し得る。
- 構造と位置符号化を同時に変えていて、どちらの効果かは分けられない。パラメータも KDA が約4%多い。
- 学習率は Transformer と同じ値で、どちらにも合わせていない。AdamW の重み減衰は `a_log` と `dt_bias` にもかかっている。参照実装はこれらを除外している。
- 文脈は 512 で、長文の利点は測っていない。
- 生成された文章に、はっきりした質の差は見えなかった。どちらも事実と論理は成り立っていない。

## メモリの見張り

学習中に [train/watchdog.py](../../train/watchdog.py) を付けた。途中から付けたので、最初の約15分は記録がない。記録の範囲で、空きメモリの最小は 4%、スワップの最大は 2.81GB だった。空き 5% 未満が3回続く条件には達せず、止めていない。この設定は 8GB 機では余裕が小さい。
