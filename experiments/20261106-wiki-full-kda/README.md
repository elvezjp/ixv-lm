# 2026-11-06 日本語 Wikipedia 全量の学習（KDA ハイブリッド 10M）

## 目的

KDA ハイブリッドと Metal カーネルが、M2 8GB の Mac mini で長時間の学習に耐えるかを確かめる。日本語 Wikipedia の全量を、1周ぶんのトークン数を目標に回した。

**途中で止めた。** 687,500 ステップの予定に対し、約311,000 ステップ（約45%）で停止した。学習率を下げる区間には入っていない。

## 条件

| 項目 | 内容 |
|---|---|
| マシン | Apple M2、メモリ 8GB（Mac mini） |
| データ | [wikimedia/wikipedia](https://huggingface.co/datasets/wikimedia/wikipedia) `20231101.ja` の全15分割（CC BY-SA 3.0 / GFDL、3.9GB） |
| トークン | 語彙 16,384 の byte-level BPE。1,389,467 文書、1,409,239,222 トークン、1.886 文字/トークン、4.857 バイト/トークン。末尾の 100万トークンが検証 |
| モデル | KDA ハイブリッド（KDA 3：全注意 1）、11,042,456 パラメータ、8層（KDA 6、全注意 2）、d=256、4ヘッド、NoPE |
| 学習 | バッチ 4 × 512 トークン、AdamW、学習率 1e-3、ウォームアップ 500、末尾20%で減衰、fp32 |
| 読み方 | 位置は無作為の復元抽出。全文書を1回ずつ読むわけではない |
| 検証 | 25,000 ステップごと、32 バッチ（約6.6万トークン） |
| 保存 | 25,000 ステップごと。1回約130MB |

Wikipedia の本文は実験用で、本番のデータの採否は別に決める。

125,000 ステップ以降、検証損失はほぼ横ばいだった。225,000 ステップから先の差は 0.01 で、検証が 32 バッチだけなので測定の揺れと区別できない。

パラメータの約20倍のトークンという目安では、11M のモデルは約2億トークンで足りる。横ばいの原因はモデルの小ささと、学習率が一定のままであることの両方が考えられるが、切り分けていない。

この検証の文章は [5,000 ステップの実験](../20261106-kda-speed/README.md)と違うので、損失の値は直接比べられない。

## 運用の記録

| 時刻 | 出来事 |
|---|---|
| 04:29 | 開始 |
| 18:55ごろ | スワップが約3分半で 1.07GB から 6.5GB へ増加 |
| 18:59 | 見張りが 6GB 超えを3回連続で検知し、学習を停止（292,000 ステップの直後） |
| 18:59 | `ckpt-275000` から `--resume` で再開。17,000 ステップをやり直し |
| 19:00〜19:24 | スワップが再び 5.94GB まで増加。Chrome を閉じると 1.6GB に低下 |
| 20:47 | 手動で停止（約311,000 ステップ）。`ckpt-300000` より後の約11,000 ステップは保存なし |

見張りの記録では、空きメモリの最小は 13%、スワップの最大は 6.56GB だった。OS は落ちなかった。

スワップの増加は、Chrome（76プロセス、約2.5GB）が原因と見ている。閉じた直後に下がったことが根拠で、18:55 の増加そのものの原因は確かめていない。学習のピークメモリは 1.72GB のままだった。

再開の後、学習損失は止まる前の値の続きになった（280,000 ステップで 4.80）。

## 分かったこと

- M2 8GB で、KDA ハイブリッドの学習を16時間以上続けられた。速度は落ちなかった。
- 見張りと `--resume` は、実際の停止で働いた。
- 学習中に Chrome を使うと、8GB では上限に届く。

## 分からないこと

- KDA が Transformer より良いか。同じ条件の全量の Transformer は回していない。
- 学習率を下げると損失がどこまで下がるか。
- 長い文脈での性能。学習は 512 トークンだけで、KDA の強みは試せていない。
- 種を変えたときの揺れ。

## 残り

- `train.py` の速度の記録に誤りがある。区間の途中で検証や保存が入ると、計測の開始時刻だけが戻り、ステップ数は戻らない。26,000 と 76,000 ステップの行は約23,000 トークン/秒と倍に出た。上の中央値からはこの2行を除いた。
- `a_log`、`dt_bias` に重み減衰がかかったまま。

## 再現

`--steps 375000` にして `ckpt-300000` から再開すると、300,000 ステップから学習率が下がり始める。

```bash
cd train
caffeinate -i ../.venv/bin/python train.py --data ~/ixv-lm-data/processed/wiki-ja-16k-full \
  --run ~/ixv-lm-data/runs/wiki-full-kda --attn-every 4 --no-rope --steps 687500 --batch-size 4 \
  --warmup 500 --log-every 2000 --eval-every 25000 --save-every 25000 --eval-batches 32
../.venv/bin/python watchdog.py --pid <学習の PID> --log ~/ixv-lm-data/runs/wiki-full-kda/watchdog.jsonl --interval 30
```
