# 2026-11-08 v1 の事前学習（0.3B、M3 Ultra）

## 目的

v1 の本線の事前学習。学習率を一定にして走り続け、数日ごとに途中の保存から分かれて学習率を下げ、会話の追加学習をしてリリースする（2026-11-08 に決めた進め方）。

0.3B に決めた（2026-11-08）。本線を止めずに続けるので、回を重ねるほど良くなる大きさにした。パラメータの約20倍のトークン（約66億）に、約14日で届く。

学習率 4e-4 は、0.1B の 6e-4 より少し下げた。大きいモデルほど下げるのが通例で、0.3B で比べてはいない。

## リリースの分かれ方

本線の保存 `ckpt-N` を新しい run にコピーし、`--resume --steps N+D --decay-frac D/(N+D)` で D ステップだけ学習率を 0 まで下げる。train.py の学習率の式では、これで N から下がり始める。分かれた run で会話の追加学習をしてリリースする。GPU は1つなので、分かれた学習の間は本線を止め、終わったら本線を最新の保存から再開する。分かれるのは `train/branch_release.py`（本線が ckpt-N を保存するのを待って止め、コピーして下げ始める）。

r2 からは `train/release.py` 1本で通す。重い処理を1つずつ順に走らせる。

1. 分かれる
2. 学習率を下げきるのを待つ
3. 会話の追加学習（tokens の書式）
4. ツール呼び出しの採点（`train/eval_tools.py`）
5. 本線の再開。途中で失敗しても、本線だけは必ず再開する

進み具合は `~/ixv-lm-data/runs/v1-0.3b-r2.release.jsonl` に書く。r2 は 2026-11-13 02:40 に仕掛けた（本線は ckpt-62000）。Mac を再起動すると、仕掛けは消える。

r2 は 08:07 に分かれ、16:02 に下げ終わり、追加学習（74,501 件、696 ステップ、最後の損失 2.59）と採点を経て 17:29 に本線を ckpt-80000 から再開した。

## 再現

```bash
R=~/ixv-lm-data/runs/v1-0.3b
nohup .venv/bin/python train/supervise.py --run $R -- --data ~/ixv-lm-data/processed/v1 \
  --steps 200000 --decay-frac 0 --lr 4e-4 --warmup 2000 --batch-size 16 --seq-len 2048 \
  --log-every 100 --eval-every 1000 --eval-batches 32 --save-every 500 --keep-last 3 --keep-every 10000 \
  --attn-every 4 --no-rope --dim 1024 --n-layers 20 --n-heads 16 --hidden-dim 2816 --compute-dtype bfloat16 \
  > $R/supervisor.out 2>&1 &
```

## r3 に向けたツールのデータの直し（2026-11-14 決定）

文の型には触らず、`make_tool_sft.py` の作り方と混ぜ方だけを変えた（`tool-v2.jsonl`、seed 2、6,000 件）。

- 作業の重み：read_lines 3、ls_count 2、grep_none 1.5、ほかは 1
- read_lines の行数（limit）を 1〜30 に散らした（r2 は 3〜11）
- read_first_line の limit を 5 固定から 1〜10 に散らした。r2 が行の指定でも limit を 5 にしがちだったのは、これのまねと見た
- ls_count は答えの数を 1〜12 から先に均等に選ぶ（8 割）。前は「1 個」が半分で、r2 も 1 個と言いがちだった
- 採点：引数は意味が同じなら正解（offset: 1 の有無、1行目の limit）。grep_none の答えは空白の違いを問わない。同じ問題の判定にツールの結果も含め、作業ごとに 50 問ずつ。問題は `tool-eval-v2.jsonl`（seed 3）で、tool-v1 と tool-v2 の両方と同じものを外す
- r3 の仕掛けは、採点のあとに r2 も同じ問題で採点し直す（`--compare`）。r2 の上の表の点数は、古い採点のもの
- 通しの採点を足した（2026-11-16 決定）。モデル自身の呼び出しを、その問題の仮のフォルダで実際に動かし、その結果から答えを書かせる。本番に近い点。`tool-eval-v2.jsonl` は同じ seed で `--keep-files` を付けて作り直した（問題は前と同じことを確かめた。前のものは `tool-eval-v2.nofiles.jsonl`）。r2 を CPU で 6 問だけ試して動くことを確かめた

## 真ん中の層を何回も通す試し（2026-11-22、学習なし）

真ん中の層を何回も通す案の V0（真ん中を続けて通すだけ）を、r4 の重みのまま、答えを出すときだけ当てはめた（`train/try_loop.py`、CPU）。入口 4 層、真ん中 12 層（4〜15）、出口 4 層。
