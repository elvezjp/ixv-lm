# 2026-11-08 v1 のデータとトークナイザー

## 目的

v1 の事前学習に使うデータを、加工済みのデータから混ぜて作る。語彙を 65,536 に増やし、英語とコードも扱えるトークナイザーにする。

## 加工

`corpus/clean.py` で、取得したデータを Parquet の text 列にそろえた。どのデータにも、NFC の正規化、行末の空白と3行以上の空行の整理、20文字未満の文書の除外、本文が同じ文書の除外をかけた。

| データ | 線引き | 文書 | 文字数 |
|---|---|---:|---:|
| FineWeb2 Edu Japanese | score 3.0 以上（2026-11-08 決定） | 57,199,388 | 1,024億 |
| FinePDFs 日本語 | 教育スコアのページ平均 1.2 以上（2026-11-08 決定） | 3,226,832 | 141億 |
| 日本語 Wikipedia | なし。タイトルを本文の前に付けた | 1,388,501 | 26.6億 |
| e-Gov 法令 | XML から本文を取り出し「第一条　…」の形に整えた | 10,288 | 5.0億 |
| 青空文庫 | ルビと注記を除き、底本と入力者の情報は残した | 17,342 | 2.4億 |
| 書籍（仕様駆動開発） | なし | 16 | 23万 |
| SDD リポジトリ | なし | 23 | 28万 |
| 画面中心主義の資料 | docx の段落を取り出した | 5 | 4万 |

FineWeb2 と FinePDFs の重複除去はファイルの中だけで行った。元のデータは MinHash で重複除去済みである。FinePDFs の OCR 崩れは、日本語に OCR 品質の指標がないため、まだ除いていない。

## トークナイザー

| 項目 | 内容 |
|---|---|
| 方式 | byte-level BPE、語彙 65,536。数字は1桁ずつに分け、英語とコードは単語の区切りで分ける |
| 学習のサンプル | 約1GB。FineWeb2 400MB、FinePDFs 150MB、Wikipedia 150MB、青空文庫 50MB、法令 50MB、自社の文章すべて、FineMath（英語）120MB、GitHub のイシュー 80MB |
| 特殊トークン | `<|endoftext|>`（id 0）、`<|pad|>`、`<|system|>`、`<|user|>`、`<|assistant|>`、ツール呼び出しと思考の印、予備 21 個。語彙は後から変えられないので先に確保した |
| 時間 | 246秒。ピークメモリ 80.6GB |

FineMath と GitHub のイシューは、トークナイザーの学習だけに未加工のまま使った。GitHub のイシューには個人情報が残っているが、学習のデータには入れていない。

1トークンあたりの文字数（新 / 旧の 16,384 語彙）。

| 文章 | 新 | 旧 |
|---|---:|---:|
| FineWeb2 | 2.16 | 1.82 |
| FinePDFs | 1.70 | 1.44 |
| Wikipedia | 1.84 | 1.93 |
| 書籍 | 2.28 | 1.91 |
| 英語（FineMath） | 3.01 | 1.89 |
| Python | 2.67 | 1.75 |

旧版は Wikipedia だけで作ったので、Wikipedia では旧版が少し良い。エンコードして戻すと、どの文章も元に一致した。

## 混合

指定は `corpus/mix-v1.json`、作るのは `train/prepare_mix.py`。

| データ | トークン | 繰り返し | 割合 |
|---|---:|---:|---:|
| FineWeb2 | 35.0億 | 1 | 55.2% |
| FinePDFs | 10.0億 | 1 | 15.8% |
| Wikipedia | 14.9億 | 1 | 23.5% |
| 法令 | 2.1億 | 1 | 3.4% |
| 青空文庫 | 1.3億 | 1 | 2.1% |
| 書籍 | 10万 | 10 | 0.016% |
| SDD リポジトリ | 11万 | 10 | 0.018% |
| 画面中心主義の資料 | 2万 | 10 | 0.003% |
| 合計 | 63.4億 | | |

FineWeb2 と FinePDFs は、必要な量に足りるファイルを全体から等間隔に選んだ。検証は、量の多い5つのデータの先頭から約20万トークンずつ、計約105万トークンで、学習には入れていない。

自社の文章は、10回繰り返しても全体の 0.04% である。

## 起きたこと

- 最初の作り方では、自社の文章がすべて検証に回り、学習に入っていなかった。データごとに先頭の20万トークンを検証に回す作りで、自社の文章は合わせても20万トークンに届かなかった。量の少ないデータは検証に回さないように直し、学習に入るトークンが 0 のデータがあれば止まるようにした。
- FinePDFs の加工を 12 並列で回しながら GPU の計測を重ね、止められた。並列を 4 に減らし、途中から再開できるようにした（README の「学習マシンでの運用」）。

## 再現

```bash
cd train
../.venv/bin/python ../corpus/clean.py finepdfs-ja --workers 4
../.venv/bin/python prepare_mix.py ../corpus/mix-v1.json --out ~/ixv-lm-data/processed/v1 --step tokenizer
../.venv/bin/python prepare_mix.py ../corpus/mix-v1.json --out ~/ixv-lm-data/processed/v1 --step tokens
```

所要時間は、トークナイザーが約4分、トークン化が約19分（12スレッド、ピークメモリ 24GB）。
