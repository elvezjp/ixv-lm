# 2026-11-06 最小の学習ループ（10M パラメータ）

## 目的

データの取得からトークン化、学習、再開、生成までが1本につながるかを確かめる。性能を出す実験ではない。M5 Ultra の速度の参考にもならない。

## 条件

| 項目 | 内容 |
|---|---|
| マシン | Apple M2、GPU 10コア、メモリ 8GB、macOS 27.2 |
| 環境 | MLX 0.32.4、tokenizers 0.23.3 |
| データ | [wikimedia/wikipedia](https://huggingface.co/datasets/wikimedia/wikipedia) `20231101.ja` の `train-00000-of-00015.parquet`（CC BY-SA 3.0 / GFDL、612MB） |
| SHA-256 | `4751c14478e712fd637bd83c2cf3537b0e299ea5115e9a78ddededf42f34c29d` |
| トークン | 語彙 16,384 の byte-level BPE。43,776 文書、1億2,004万トークン、1.90 文字/トークン |
| モデル | Transformer、10,621,184 パラメータ、8層、d=256、入出力の重み共有 |
| 学習 | 5,000 ステップ、バッチ 4 × 512 トークン（計約1,024万トークン）、AdamW、学習率 1e-3、末尾20%で減衰、fp32 |

Wikipedia の本文は実験用で、本番のデータの採否は別に決める。

## 結果

| 項目 | 値 |
|---|---|
| 検証損失 | 8.105（500 ステップ）→ 6.009（5,000 ステップ） |
| 検証 bits-per-byte | 2.314 → 1.716 |
| 速度 | 中央値 18,779 トークン/秒、1.2 TFLOPS（6ND 換算） |
| ピークメモリ | 1.69GB |
| 所要時間 | 9.2 分 |
| チェックポイント | 1回 122MB |
| 2048×2048 fp32 行列積の単体 | 2.1 TFLOPS |

検証損失は最後まで下がり続けていて、学習量が足りていない。

生成の例（温度 0.7、続きの一部）：

> 東京都は、大阪市区であるが、また、東京都は京都府の墓地を持っていることが多い。

日本語の形と Wikipedia の文体は出るが、事実と論理は成り立っていない。この規模と学習量では想定どおりである。

## 確かめたこと

- **途中再開：** 通しの40ステップと、20ステップで止めて再開した40ステップで、検証損失が一致した（8.841179847717285）。重みの差は最大 8.9e-7。
- **メモリ：** バッチ 16 × 512 では、スワップが約10GBに達し、5分たっても10ステップ進まなかった。他のアプリも動いている状態での結果である。

## わかったこと

- 8GB 機で 10M の学習は回る。ただしバッチの上限は低い。
- 語彙の出力層の logits が大きいので、大きいバッチには勾配累積か、損失の分割計算が要る。
- 再開の仕組みは本番の土台に使える。線形層の比較は、この実装を対照にできる。

## 再現

[README](../../README_ja.md) の「最小の学習を動かす」のとおり。学習の引数は次のとおり。

```bash
.venv/bin/python train/train.py --data ~/ixv-lm-data/processed/wiki-ja-16k --run ~/ixv-lm-data/runs/mini-10m --steps 5000 --batch-size 4 --warmup 100 --log-every 250 --eval-every 500 --save-every 1000 --eval-batches 32
```
