# 2026-11-06 KDA のチャンク計算の高速化

## 目的

[KDA の最初の実装](../20261106-kda-reference/README.md)は Transformer の約4分の1の速度で、メモリも約2倍だった。Metal カーネルを書かずに、計算の組み替えだけでどこまで改善するかを確かめる。

## 変更

チャンク内の `[C, C, K]` の減衰の表を丸ごと作るのをやめた。

- チャンクを小さなブロックに分け、表を作るのは対角ブロックだけにする。
- ブロック間は行列積で計算する。ブロックの境目の `g` を基準にすると、i > j で両側の指数がどちらも 0 以下になり、`exp` が溢れない。
- 既定はチャンク 32、ブロック 8。

## 結果

マシンは M2 8GB。測定は各1回。

1層の順伝播と逆伝播（バッチ 4、長さ 512、4ヘッド、次元 64、10回の平均）：

| チャンク | ブロック | 時間 | ピークメモリ |
|---:|---:|---:|---:|
| 32 | 変更前 | 43.5 ms | 0.85GB |
| 16 | 16 | 33.3 ms | 0.59GB |
| 32 | 16 | 26.4 ms | 0.54GB |
| **32** | **8** | **22.5 ms** | **0.47GB** |
| 32 | 4 | 23.2 ms | 0.47GB |
| 64 | 8 | 23.6 ms | 0.50GB |

学習全体（10M の KDA ハイブリッド、バッチ 4 × 512、60 ステップ）：

| 項目 | 変更前 | 変更後 | Transformer |
|---|---:|---:|---:|
| 速度 | 5,017 トークン/秒 | 約7,580 トークン/秒 | 18,779 トークン/秒 |
| ピークメモリ | 3.36GB | 1.76GB | 1.69GB |

変更前と Transformer は 5,000 ステップの中央値で、変更後は 60 ステップの値である。

## 正しさ

- 参照実装（`experiments/20261106-kda-reference/compare.py`）との最大の相対誤差は 1.62e-6 で、変更前の 1.56e-6 と同じ水準。
- 1ステップの対数減衰が最大 -100 の極端な条件で、勾配はすべて有限だった。逐次形式との勾配の相対誤差は最大 3.6e-5。

## 順に回す部分の組み替え

状態の更新を `S' = P S + B` にまとめ、`P` と `B` と出力を全チャンク同時に計算するようにした。順に回すのは行列積1回だけになる。

| 項目 | 組み替え前 | 組み替え後 |
|---|---:|---:|
| KDA の核の順逆伝播 | 22.5 ms | 20.6 ms |
| 学習全体 | 約7,580 トークン/秒 | 約8,000 トークン/秒 |
| 学習全体のピークメモリ | 1.76GB | 2.08GB |

参照実装との最大の相対誤差は 1.62e-6 のまま。極端な減衰（-100）でも勾配は有限で、逐次形式との相対誤差は最大 6.1e-5。

## 時間の内訳

`profile_parts.py` と `profile_layer.py` で測った。いずれも順逆伝播で、バッチ 4、長さ 512。

| 部品 | 時間 |
|---|---:|
| KDA の層全体 | 28.6 ms |
| うち KDA の核 | 20.6 ms（順伝播だけなら約 5 ms） |
| 全注意の層 | 5.1 ms |
| FFN | 3.7 ms |
| 短畳み込み（1個、KDA の層に3個） | 1.0 ms |
| 出力層と損失 | 27.1 ms |

1ステップ約256ms のうち、KDA の6層で約172ms を使っている。核の時間は特定の1か所に集中していない（組み替え前の測定で、チャンク内の計算 6.7ms、逆行列 1.7ms、順に回す部分 9.6ms）。

Metal カーネルで核を 2.5 倍速くできたと仮定すると、学習全体は約1.4倍になる（推定）。

## Metal カーネル

チャンク内の `A_q`、`A_k` を [train/kda_metal.py](../../train/kda_metal.py) の Metal カーネルにした。順伝播も逆伝播も手書きで、`mx.custom_function` で MLX の自動微分につなぐ。減衰の表をメモリに作らず、スレッドの中で `exp` を取る。スレッドグループメモリは約25KB で、M2 と M3 の 32KB に収まる。

| 項目 | MLX の演算 | Metal |
|---|---:|---:|
| チャンク内の計算の順逆伝播 | 6.66 ms | 0.86 ms |
| KDA の核の順逆伝播 | 20.6 ms | 12.1 ms |
| KDA の層全体 | 28.6 ms | 20.1 ms |

正しさ：`check_metal.py` で MLX の演算との最大の相対誤差は 5.6e-7。対数減衰 -100 でも勾配は有限。参照実装との最大の相対誤差は 1.62e-6 のまま。

## 5,000 ステップの通し学習

KDA の3つの比較は、同じデータ、同じ手順、同じ種。

| 項目 | Transformer | KDA（最初の実装） | KDA（Metal） |
|---|---:|---:|---:|
| 検証損失 | 6.009 | 5.884 | 5.909 |
| 検証 bits-per-byte | 1.716 | 1.680 | 1.687 |
| 速度（中央値） | 18,779 | 5,017 | 10,124 トークン/秒 |
| 所要時間 | 9.2 分 | 38.5 分 | 17.4 分 |
| ピークメモリ | 1.69GB | 3.36GB | 1.73GB |

Metal の実験の見張りの記録では、空きメモリの最小は 16%、スワップの最大は 4.4GB だった。

最初の実装と Metal で、検証損失が 0.025 違う。途中までは 1,500 ステップで 0.001 差だったが、4,000 ステップで 0.007、5,000 ステップで 0.025 に広がった。計算順の違いによる丸め誤差が学習で増幅した可能性があるが、確かめていない。核の数値照合は一致しているので実装の誤りとは見ていない。ただ、この差と同じ程度の揺れが実験にはあると見るべきで、種を変えた比較が要る。

## 順に回す部分の Metal カーネル

`profile_stages.py` で核を測り直すと、順に回す部分が最大だった（全体 12.1ms のうち 5.2ms。チャンク内 1.2ms、`w`、`u` の準備 2.7ms、`P`、`B` の組み立て 1.5ms、出力 1.5ms）。

`S' = P S + B` を1回のカーネルで回す `linear_scan` を書いた。逆伝播も同じ形の漸化式なので、同じカーネルに転置した行列を逆順で渡す。`dP` は全チャンク同時の行列積で求める。

| 項目 | 変更前 | 変更後 |
|---|---:|---:|
| KDA の核の順逆伝播 | 12.1 ms | 8.8 ms |
| KDA の層全体 | 20.1 ms | 16.3 ms |
| 学習速度（中央値） | 10,124 トークン/秒 | 11,343 トークン/秒 |
| 所要時間（5,000 ステップ） | 17.4 分 | 15.4 分 |
| ピークメモリ | 1.73GB | 1.72GB |

参照実装との最大の相対誤差は 1.62e-6 のまま。検証損失は 5.901、bits-per-byte は 1.685。見張りの記録では、空きメモリの最小は 20%、スワップの最大は 1.25GB だった。

同じ構成の KDA の検証損失は、これで 5.884、5.909、5.901 の3つになった。種は同じで計算順だけが違う。この幅 0.025 は、実験の揺れの目安になる。

## 効かなかったこと

| 試したこと | 結果 | 扱い |
|---|---|---|
| `mx.fast.cross_entropy` | 出力層と損失が 27.8ms → 27.3ms。時間の大半は語彙の行列積 | 採用しない |
| q、k、v の投影と畳み込みの統合 | 層が 16.3ms → 16.4ms、ピークメモリが 1.86GB に増加 | 元に戻した |

## 残り

- 速度はまだ Transformer の約6割。
- 検証損失の幅の原因は未確認。
- `w`、`u` の準備（約2.7ms）は Metal にしていない。核の外に約7.5ms ある。
- カーネルはヘッド次元 64 までを想定している。128 にすると 32KB に収まらず、分割が要る。
- M3 では動かしていない。
- 長い文脈での速度は測っていない。
