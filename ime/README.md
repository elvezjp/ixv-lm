# IXV かな漢字（この Mac で学習したもので動く日本語入力）

かな漢字変換の段 3（段 0 は [記録](../experiments/20261123-kanji-stage0/README.md)、段 1 は [記録](../experiments/20261124-kanji-stage1/README.md)）。2026-11-24 決定。
azooKey（macOS 版）と Zenzai はお手本として読むだけで、コードは借りていない。辞書もモデルも、この Mac で Wikipedia から作った。

## しくみ

| 部品 | 中身 |
|---|---|
| [engine.py](engine.py) | 変換の中身。辞書の下書き → モデルの検算 → 文節ごとの候補 |
| [server.py](server.py) | 変換サーバー。`127.0.0.1:18190` だけで受ける |
| [macos/](macos/) | 入力メソッド `IXVKanji.app`（Swift、InputMethodKit）。Xcode なしで swiftc で作る |
| [../corpus/make_kanji_dict.py](../corpus/make_kanji_dict.py) | 辞書。Wikipedia の文を Sudachi で区切り、語（表層・読み・品詞）と 2 語のつながりを数える |
| [eval_engine.py](eval_engine.py) | AJIMEE-Bench の 200 問で、下書き（と検算）を採点する |

変換の進め方（azooKey の Zenzai と同じ考え方）：

1. 辞書の語を読みで引き、2-gram（Witten-Bell で 1-gram と混ぜる）の確からしさで、読みに合う並びをビームで探す。これが下書き。数の読み（サンビャク → ３００）と、辞書に無いカタカナ語（カタカナのまま）も並びに入れる。
2. 段 1 のモデル（文字単位、0.1B、[記録](../experiments/20261124-kanji-stage1/README.md)）が下書きを 1 回の計算で検算する。最初に食い違った位置で、モデルの字を条件に辞書の探索をやり直す。直した案は、モデルから見て直す前より確からしいときだけ採る。下書きは辞書の読みに縛られているので、読みに合わない字は出ない。
3. 下書きを文節（語 ＋ 後ろの助詞・助動詞・接尾辞・記号）に分け、文節ごとに候補を並べる：ユーザー辞書 → 学習した変換 → 下書き → 辞書の n-best → モデルの書いた変換のうち、Sudachi で読み直して読みの合うもの → ひらがな → カタカナ。

## 打ち方

| キー | 打っている途中 | 変換中 |
|---|---|---|
| 英字 | ローマ字でかな（`nn` で「ん」） | 確定して、続けて打つ |
| Shift＋英字、数字 | そのまま入る | 確定して、続けて打つ |
| スペース | 変換 | 次の候補 |
| ↓ ↑ | — | 次・前の候補 |
| ← → | — | 文節を移る |
| Shift＋← → | — | 文節を縮める・伸ばす（後ろは変換し直す） |
| 1〜9 | — | 候補を選んで次の文節へ（最後なら確定） |
| Enter | かなのまま確定 | 全部を確定（選んだ変換を覚える） |
| 削除 | 1 字消す | かなに戻る |
| Esc | 消す | かなに戻る |
| F6〜F10 | ひらがな、カタカナ、半角カタカナ、全角英字、半角英字 | 同じ |
| 英数・かな | 直接入力・日本語入力に切り替え | 確定してから切り替え |

- 確定した文の最後の 40 字を、左の文脈としてモデルに渡す。何も打っていないときの Enter（改行）で空にする。
- サーバーにつながらないときは、ひらがなとカタカナだけが候補になる。

## 予測変換・ライブ変換・日付と記号

- 予測変換：2 字以上打つと、読みがそれで始まる語を窓に出す（学習したものが先）。Tab で選び（もう一度で次）、Enter で確定。
- ライブ変換：スペースを押さなくても、打つたびに変換した形を見せる（モデルは使わず、辞書の下書きだけ）。Enter でその形のまま確定、スペースでふつうの変換に入る。
- 日付・時刻・記号：「きょう」「あした」「きのう」で日付、「いま」で時刻、「ことし」で年、「きごう」「やじるし」「まる」「かっこ」などで記号が、候補の 2 番目から並ぶ。

## 設定

入力メニュー（メニューバーの「漢」）の「設定…」で開く。変えたものは、次に打つときから効く。中身は UserDefaults（`jp.co.elvez.inputmethod.IXVKanji`）なので、`defaults` でも変えられる。

| 分類 | 項目（キー、既定） |
|---|---|
| 変換 | ライブ変換（`liveConversion`、切）、予測変換（`prediction`、入）、モデルで検算する（`useModel`、入。切ると辞書だけで速い）、前に確定した文を文脈として渡す（`useContext`、入） |
| 入力 | 句読点（`punctuation`、0「、。」1「，．」2「，。」）、スペースを全角で（`fullWidthSpace`、切。Shift＋スペースで半角）、数字と英字を全角で（`fullWidthAlnum`、切） |
| 候補の窓 | 一度に出す候補の数（`candidateCount`、9）、文字の大きさ（`fontSize`、15） |
| 学習と辞書 | 学習を使う（`learning`、入）、学習を消す、ユーザー辞書を編集（テキストエディットで開く）、置き場所を開く |
| 変換サーバー | つながっているか、重み・辞書・計算機（CPU / GPU） |

入力メニューの「ユーザー辞書を編集…」からも、ユーザー辞書を開ける。

## 学習とユーザー辞書

置き場所は `~/Library/Application Support/IXVKanji/`（サーバーの `--store` で変えられる）。

- `history.tsv`：確定した文節のうち、候補を選び直した（スペース、↓↑、数字キー）ものの（読み、変換、回数）。下書きのまま確定した文節は覚えない。同じ読みでは、次から 1 番目に出す。ただし 2 字までの読み（ね、が など）は、下書きより前には出さない。手で直しても、次の変換から効く。消せば忘れる。
- `user_dict.tsv`：読み（ひらがなかカタカナ）＜タブ＞変換。UTF-8 で保存する（読めない行は飛ばす）。保存すれば、次の変換から使う（サーバーの再起動は要らない）。学習した変換より先に出す。
- 変換サーバーは、この Mac の入力メソッドからの要求だけを受ける（Host が 127.0.0.1 か localhost、Origin なし、JSON）。Web ページからは呼べない。

## 動かし方

1. 辞書を作る（1 回だけ、CPU で約 10 分）。

   ```
   .venv/bin/python corpus/make_kanji_dict.py --src ~/ixv-lm-data/clean/wikipedia-ja \
     --items ~/ixv-lm-data/eval/ajimee/evaluation_items.json --out ~/ixv-lm-data/ime/dict-v2
   ```

2. どの辞書と重みで動かすかを `~/ixv-lm-data/ime/current.json` に書く（作り直しのスクリプトが書き換える）。

   ```
   {"dict": "~/ixv-lm-data/ime/dict-v2 の絶対パス", "run": "…/runs/kanji-char-0.1b", "data": "…/processed/kanji-char-v1"}
   ```

3. 変換サーバーを動かす。手で動かすなら `ime/run_server.sh`。ログインしたら自動で動くようにするなら `ime/macos/install-server.sh`（`~/Library/LaunchAgents/jp.co.elvez.ixvkanji.server.plist` を置く。止まっても launchd が動かし直す。外すのは `uninstall-server.sh`）。
   - 計算機は自動で選ぶ（`--device auto`）。ふだんは GPU、`train/train.py` が動いている間は CPU（学習と GPU を重ねない）。

4. 入力メソッドを作って入れる。

   ```
   ime/macos/build.sh
   ime/macos/install.sh
   ```

5. 初回だけ：システム設定 → キーボード → 入力ソース → 「＋」→ 日本語 → 「IXV かな漢字」を足す。出てこないときはログアウトしてから。

## 配る形（Hugging Face）

重みと辞書は `elvezjp/IXV-LM-Kanji-0.1B` に置く（2026-11-24 決定：名前はこれ、ゲート付き、まずプライベート）。重みと辞書は CC BY-SA 4.0、コードはこのリポジトリの MIT。

- 取り出し：`ime/export_release.py`。学習用のチェックポイントから重みだけを bfloat16 で書き、手元のパスは書き出さない。取り出したもので AJIMEE-Bench が元と同じ（検算つき 0.68）ことを確かめた。
- モデルカードと NOTICE は `~/ixv-lm-data/release/IXV-LM-Kanji-0.1B/` にあり、そのまま上げる。
- 使う人は `hf download` で取り、`current.json` の dict に `…/dict`、run と data にそのフォルダを書く。engine.py は、フォルダの直下に model.safetensors があれば、それを読む。

## 採点（AJIMEE-Bench、200 問、下書きの全体の完全一致）

| 方式 | acc@1 | MinCER |
|---|---|---|
| v1 に追加学習（段 0、モデルだけ） | 0.14 | 0.316 |
| 辞書の下書きだけ（数とカタカナ語を足す前） | 0.655 | 0.051 |
| 辞書の下書きだけ（数とカタカナ語を足した後、dict-v1） | 0.650 | 0.054 |
| 辞書の下書きだけ（ほかの読みを足した dict-v2） | 0.650 | 0.051 |
| 段 1 のモデルだけ（ckpt-13000） | 0.62 | 0.064 |
| 辞書の下書き（dict-v2）を段 1（ckpt-13000）が検算 | 0.685 | 0.042 |
| 最新の Wikipedia で作り直した辞書（dict-v3）と段 1（kanji-char-0.1b-w2611）、いま | **0.68** | **0.044** |

- 辞書も AJIMEE-Bench も Wikipedia から作っている。問題の文そのものは辞書から外したが、同じ記事のほかの文は入っている。
- 数とカタカナ語の重みは、AJIMEE-Bench の外れ方を見ながら決めた。この 200 問は、もう手つかずの物差しではない。
- 検算は、学習を終えた重みで 0.650 → 0.685 に上がった（GPU で 1 問 0.094 秒 → 0.16 秒）。学習途中（ckpt-2000）のモデルは「明日」「大人」「私は」をひらがなに直してしまうので、直した案は、モデルの確からしさが 1.0（対数）以上上回るときだけ採るようにした（`verify_margin`）。最新の Wikipedia で学習し直した後も検算で点が上がったので、1.0 のままにする。

## 使ってみて見つかった間違い

| 日付 | 打った読み | 出たもの | 欲しかったもの | わけ（見立て） |
|---|---|---|---|---|
| 2026-11-24 | ふつうにつかえるね | 普通に使える音 | 普通に使えるね | 文の終わりの「ね」が 1 文節に分かれ、1 位が「音」になる。辞書とモデルの元が Wikipedia で、話し言葉の終助詞がほとんど無い |

## まだ無いもの（azooKey にあって、ここに無いもの）

- スペースで変換したときも、返事を待たずに打ち続けられるようにする（いまは待つ。CPU で 0.5〜1.5 秒、GPU なら短くなる）。予測変換とライブ変換は、待たずに問い合わせるようにした（2026-11-24）。
- 絵文字と顔文字の候補（一覧を作る元のデータを、まだ決めていない）。
- 予測変換で選んだものの学習。
